Version: 0.11.1
Date: 2026-10-16
  Changed:
    - A destination that arrives with no kind is named in the log instead of being
      skipped quietly. Without it, a topology that carried no kinds looked exactly like
      working code: no surfaces were created and nothing said why.

Version: 0.11.0
Date: 2026-10-16
  Added:
    - Every planet's surface is created on every server, when the topology arrives. A
      split world gives each server its own save, so a surface exists only where its save
      made it -- and the remote view that routing depends on has nothing to click on a
      planet this server has never had. Chunks are generated when something needs them, so
      an unvisited planet stays fog: nothing is rendered or charted by this.
    - report lists the surfaces this server has, which is how that is checked.
  Note:
    - The topology now names each server's kind, because only a planet has a surface to
      create; a space server's platforms are built, not created.
---------------------------------------------------------------------------------------------------
Version: 0.10.0
Date: 2026-10-16
  Added:
    - Every route a research can change by is reported, not just the two labs produce:
      started, finished, cancelled, reversed, queued and moved. A research a script or an
      action changed now reaches the manager for the same reason a player's choice does.
    - The current research's level is reported with its state. An infinite research keeps
      its name as it levels and its bar restarts, so without the level one level's progress
      is indistinguishable from the next.
    - The routing decision is taken again when a player's controller changes, which covers
      entering or leaving remote view and entering a space platform, where the surface does
      not change.
  Note:
    - Nothing here draws anything: the mod has no GUI, and the only two commands it
      registers are the manager's call interface and a status report, both for the console
      and RCON.

Version: 0.9.0
Date: 2026-10-16
  Fixed:
    - A server could never be moved onto the research the fleet is on. add_research puts
      a technology at the back of the queue, so with one already running the requested
      technology was merely queued behind it and the server stayed on its own -- the
      manager reported the shared bar while five servers researched something else. The
      running research is cancelled first, which is what makes the switch take. A
      technology the game will not accept is skipped rather than failing the sync.
  Note:
    - Two servers on the same technology cannot both be moved at once by re-adding it;
      the switch has to cancel the running one for each server.
---------------------------------------------------------------------------------------------------
Version: 0.8.0
Date: 2026-10-16
  Fixed:
    - A technology the fleet had outgrown could not be marked researched. Setting the flag
      while the game was researching that technology was dropped and the research kept
      running, so a research the manager had started could never be finished by it, and a
      fleet could sit on the same technology for good. The research is cancelled first --
      the supported way to abandon one -- and the call now reports what actually took
      rather than what it asked for.
  Note:
    - Found by driving the shared research against a running six-server stack: two
      planets contributing at once, a planet falling behind, a research finishing, and a
      planet that was stopped while it finished.
---------------------------------------------------------------------------------------------------
Version: 0.7.0
Date: 2026-10-16
  Changed:
    - research_state takes an offset and a limit and returns one page plus the total, so
      a node never depends on the whole technology list fitting in a single RCON frame.
      The tree is already past 5 KB of JSON with a full save and it only grows; the
      companion mod this stack replaced chunked its reports at 4096 bytes for the same
      reason. The node assembles the pages.
  Note:
    - Paging needs no snapshot: the manager unions what it reads on every poll, so a
      technology that shifts across a page boundary and is missed once is picked up on
      the next pass.

Version: 0.6.0
Date: 2026-10-15
  Changed:
    - The node reaches the mod through one plain command, server-connector-call, instead
      of `/c remote.call(...)`. `/c` is a script command, so every poll permanently
      marked the save as cheated, and it echoed into the chat -- a manager polling every
      few seconds filled the screen of anyone playing. A mod's own command does neither.
    - The call surface is one command name taking {"fn": ..., "args": [...]}, so the node
      depends on one thing that does not move as the interface grows.

Version: 0.5.0
Date: 2026-10-15
  Fixed:
    - Applying a research in progress did nothing. LuaForce::current_research is read
      only in 2.1 -- assigning to it fails with "is read only" -- so the shared
      research was never actually started on the receiving server. It now goes through
      force.add_research, which is the supported path, and a technology that is not
      available yet is skipped rather than failing the whole sync.

Version: 0.4.0
Date: 2026-10-15
  Features:
    - research_state reports this server's tech tree: what is researched, what is in
      progress and how far along.
    - apply_research takes the shared tree back: technologies to mark done, and where
      the research in progress stands. The manager merges every server and sends the
      result, because no server can see another's tree.
    - on_research_finished and on_research_started are queued as events, so the
      manager learns about research without waiting for a poll to notice.
  Note:
    - Every server in the stack has exactly one surface, so each one has its own copy
      of the tech tree and they drift apart the moment anybody researches anything.
      This is what stops that.

Version: 0.3.0
Date: 2026-10-15
  Features:
    - The mod reports the in-game events it cannot avoid seeing -- joins and surface
      changes -- as a bounded queue the node drains with drain_events. The manager
      cannot observe either for itself, and only the game can witness them, so this
      is the half of "an interface to Lua" that was missing.
    - The queue is capped at 64 entries: a queue nobody reads must not grow.

Version: 0.2.0
Date: 2026-10-15
  Changes:
    - The trigger is the game's own remote view. on_player_changed_surface fires when
      the surface being *viewed* changes, including a click onto another planet in
      remote view, and this mod routes on it -- so the picker is the interface the game
      already has.
    - Removed the custom travel menu, its top-bar button and the server-connector-travel
      command. They were the wrong idea: a menu this mod drew instead of using remote
      view.
  Features:
    - Routing now keys off the viewed surface rather than a menu: a planet surface maps
      to the server named after it, and any platform surface maps to the space server.
    - A routed guard keeps the handler from re-firing on a destination it has already
      acted on.
    - report includes viewing_surface, so the manager can see what a player is looking
      at and not only where their body is.

Version: 0.1.0
Date: 2026-10-15
  Features:
    - Routes a player to another server with connect_to_server.
    - Knows which planet (or the space platforms) this server handles, pushed over RCON.
    - Takes the rest of the topology over RCON, so the manager can change the destination

    - Puts a player whose body is on another server into the remote controller, with
