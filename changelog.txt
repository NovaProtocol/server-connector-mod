Version: 0.19.0
Date: 2026-10-16
  Changed:
    - The mod does nothing at all until a node tells it what it is. It is a driver: it
      reaches into the game's components and the node decides what is done with them, the
      order coming in over stdin and the event going out over stdout. A server that never
      hears from a node -- somebody's own save, a server with nothing to do with this fleet
      -- never gets an identity, and now every action in the file does nothing: no surfaces
      created, no players moved, no chunks cleared, no scenario touched. Loading it changes
      nothing.

Date: 2026-10-16
  Fixed:
    - The sweep had two copies of itself and the older one was the live one -- in Lua the

Version: 0.18.2
Date: 2026-10-16
  Fixed:
    - The sweep no longer asks for a chunk with a method this build of the game does not
      have (get_chunk), which threw from a boot-time handler and took clearing down with it
      -- including the report of what had already been taken off. The entities go first and
      now always report; chunks are deleted only if delete_chunk is there at all.
  Added:
    - surface_api, which reports which of these calls the game actually has, so the next
      question about it is answered by the game rather than guessed at.
---------------------------------------------------------------------------------------------------
Version: 0.18.1
Date: 2026-10-16
  Fixed:
    - 0.18.0 did not start. The spawn-position check called get_spawn_position with no
      argument where the API wants one, and the error came out of a boot-time tick handler,
      which is non-recoverable: every server running it quit as it loaded. The spawn
      position is set on the surface this server is for instead of being compared with
      anything, and every step of the boot work is wrapped, so a fault in one of them is a
      log line rather than a fleet that will not start.

Version: 0.18.0
Date: 2026-10-16
  Added:
    - A player standing somewhere they do not belong is put back on the surface this server
      owns. It happens only when they are not on that surface, and only after
      route_if_elsewhere has had its turn: looking at another server's planet is a journey
      and connect_to_server takes them there, and a redirect already in flight counts as
      handled, so nothing fights the connection being made.
    - A surface this server does not own is cleared on boot: every creature on it is
      destroyed and the chunks around the origin are deleted. A fleet server's save is a
      nauvis world whatever planet the server is for, so nauvis is generated -- spawn area
      and biters -- before anybody arrives, and on five of the six servers nobody ever goes
      there. Those biters are a UPS cost paid every tick by a server playing elsewhere.
    - The spawn point moves to the surface this server is for, so a player arriving without
      a body does not generate a fresh spawn area -- biters and all -- on a surface that was
      just cleared.
    - clear_surfaces, so the manager can ask for the same thing after loading a save.
  Changed:
    - The report says which surface the spawn point is on and what the last clear took.
